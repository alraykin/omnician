# Omnician

**You're becoming an Omnician.**

Omnician is **the ultimate practice companion** — a simple home base for the tools you reach for before you play. This version includes a live **Tuner** (uses your microphone) and **Rhythm** (click + drums in one room).

You do **not** need to know how to program. Follow the steps below on your computer, then open the app in a web browser.

---

## What you need

1. A computer (Mac, Windows, or Linux)
2. **Node.js** — this is a free program that lets Omnician run on your machine
   - Download the **LTS** version from [https://nodejs.org](https://nodejs.org)
   - Run the installer and click through with the default options
3. A web browser you already have (Chrome, Safari, Edge, or Firefox)

After installing Node.js, **close and reopen** Terminal (Mac) or Command Prompt / PowerShell (Windows) so the computer notices it.

---

## How to run Omnician

### 1. Open a terminal

- **Mac:** open **Terminal** (search for it with Spotlight)
- **Windows:** open **Command Prompt** or **PowerShell**
- **Linux:** open **Terminal**

### 2. Go to this project folder

Type `cd` then a space, then the folder where this project lives, then press Enter.

Example if the folder is on your Desktop and named `omnician`:

```bash
cd Desktop/omnician
```

### 3. Install what the app needs

Copy this command, paste it into the terminal, and press Enter:

```bash
npm install
```

The first time, this can take a minute. You only need it again if files were updated.

### 4. Start the app

```bash
npm run dev
```

Leave this terminal window open. You should see a message with an address like:

```text
http://localhost:43121
```

### 5. Open it in your browser

Click that address if the terminal makes it a link, or type **http://localhost:43121** into your browser.

You should see the Omnician home screen: the wordmark, then three big buttons — Tuner, Click, and Drums.

### 6. Stop the app when you are done

Click the terminal window and press **Control + C**.

  - Pitch is FastYIN (CMND + threshold + parabolic interpolation) in an AudioWorklet, with a harmonic-product-spectrum / multi-candidate check so a weak or missing fundamental is not read as its octave. Windows grow to ~2.6 periods of the lowest note (E0 ≈ 20.6 Hz, about 100–150 ms) and shrink for high strings. The detector reads the **live** AudioContext sampleRate, listens to channel 0 or the loud channel of a stereo jack (it will not average a whole audio interface together), high-passes rumble below E0, low-passes above C8, gates on SNR, and **throws away** unclear readings instead of guessing. Cents are `1200 × log2(f / target)` with targets `A4 × 2^((midi−69)/12)`. A new pluck locks to the real Hz; a held note follows the pitch (no pull-to-zero); the last good note holds as the string dies away. `npm run test:accuracy` synthesizes additive, weak-fundamental, Karplus–Strong, noisy, vibrato, and attack tones for every chromatic note E0–C8 and every string in all presets, and reports within 1 / 5 / 10 cents plus octave error. `npm run test:calibration` runs offsets at 44.1 kHz and 48 kHz.

Click, Drums, Speed Builder, tap-to-hear tones, and tuner fork tones use **one playback AudioContext**, created lazily on the first Play / tap gesture, with `navigator.audioSession.type = 'playback'` written in that same tap **before** the context is created or `resume()`d (Safari 16.4+ / iOS 17 — the `/lab/silent` step that keeps Web Audio audible when the ringer is off). The on/off switch stays on that card. **Announce** and **Precount** sit on the Speed Builder panel (with a copy in Settings). **Precount** (default on) is one shared switch: on **Drums** it counts in one bar of the current meter before the groove, even with Speed Builder off; with Speed Builder on, the same setting counts in once before each new tempo (never twice). The count uses the distinct precount click and the same beat length as the meter (`(60 / BPM) × (4 / denominator)`), then bar 1 beat 1 starts with no gap. Click only uses precount when Speed Builder is on. The goal tempo keeps looping. A large percent / BPM flash appears at each tempo change. **Announce** plays bundled neural voice clips (Kokoro af_heart) through the same audio engine as the click — not the phone’s robotic system voice. Last setup stays on this device. Old `/metronome`, `/drum-machine`, and `/rhythm?mode=` links redirect to `/click` or `/drums`.
- There are **no payments** yet. The home page no longer mentions a future subscription.

There is no account sign-in and nothing to pay. The tuner needs microphone permission. If the browser blocks the mic, allow it for this site in Settings, then tap the tuner page to try again.

## If something goes wrong

**The terminal says `npm` is not recognized, or `command not found: npm`**  
Node.js is missing, or the terminal was left open during install. Install Node.js from [nodejs.org](https://nodejs.org), then close the terminal completely and try again.

**The page will not load**  
Make sure `npm run dev` is still running, then visit http://localhost:43121

**It says the port is already in use**  
Omnician is probably already running in another terminal. Use that one, or stop it with Control + C and start it again.

**You changed files and the page looks old**  
Save the files, then refresh the browser.

### Permanent site (omnician.app)

The live site is a Cloudflare Worker that serves the Vite `dist/` folder. Client routes such as `/tuner`, `/click`, and `/drums` are covered by Wrangler's single-page-application fallback (`wrangler.jsonc`). The repo is not on GitHub, so deploys are a direct Wrangler upload — not Cloudflare Pages Git.

When Cloudflare credentials are in the environment, publish with:

```bash
npm run deploy
```

That script builds the app, then runs `wrangler deploy`. It needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. Do not put those values in the repo. They belong in Cursor **Cloud Agents → Secrets** (token as a **Runtime Secret**, account ID as an **Environment Variable**). After a change lands on `main`, run `npm run deploy` so **omnician.app** updates. Do not add a `public/_redirects` SPA rewrite — Wrangler already serves `/tuner`, `/click`, and `/drums` with `not_found_handling: "single-page-application"`.

The Worker also serves `/api/factory` and stores the built-in Drums library in the `omnician-factory` KV namespace bound as `FACTORY` (`wrangler.jsonc`). The Worker secret `FACTORY_ADMIN_PASSWORD` must stay set; there is no factory password in this repo.

## Factory editor (built-in Drums library)

The Beat library can be edited without changing code. The app loads `/api/factory/library` at startup, keeps a copy on this device, and uses the bundled grooves (including **Backbeat** and **Chameleon**) if the network request fails.

There is no button for this in the app. Open `/factory`, type the admin password, and you land on Drums with a purple **Factory editor** bar that keeps the loaded beat’s name and id. Editing notes, meter, tempo, bars, or soft notes does not rename it to Custom. **Save as default** overwrites that factory beat in place. **Save as new** asks for a name and style, then adds a new factory beat. **Rename** changes the name without creating Custom. **Delete** removes with a confirm. The **Beat library** lists style names and beat names only (descriptions stay in the data). Drag a groove in the same style group to change its menu order; that order is saved as default for everyone. **Undo** reverses the last Factory save. **History** still lists the last 20 saves. After a save, the library reloads from the server and stays on the saved beat.

Writes need a signed, httpOnly session cookie (30 days). The password is only checked on the server against `FACTORY_ADMIN_PASSWORD`. For local `npm run dev`, that value lives in `.dev.vars` (gitignored). Do not put the real production password in the repo.
